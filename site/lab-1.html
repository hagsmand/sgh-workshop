Understand Bob's capability

Learn how to use MCP, skills and modes on Bob.

Time
60 minutes
Where
Bob IDE, with the kit folder open
You build
A skill, a mode and an MCP server connection
Question
What does Khun Somchai need to order before the 9:00 truck?

Bob is only as useful as the context it has. In this lab you give it three kinds: a skill (how we write code), a mode (who Bob is for this job) and an MCP server (live access to our stock data). You will ask the same question before and after, and see the difference.

PieceWhat it isWhere it lives
ModeA role for Bob: what it is, which tools it may use, which files it may edit.bob/custom_modes.yaml
SkillA reusable set of instructions Bob follows when the task matches.bob/skills/<name>/SKILL.md
MCP serverA small program that gives Bob new tools, here: read our stock and sales.bob/mcp.json, added from Settings, MCP
1

Open the kit folder and add the skill8 min

In the Bob IDE, open the kit folder (the one with package.json in it).

A skill is a folder with a SKILL.md. The top part says what it is for. The rest is the instructions. Bob decides when to use it from the description, so the description says when to use it.

The skill is already written. It is in the kit at answers/lab1/skills/ghh-coding-standard. Copy that whole folder into .bob/skills/ in the kit folder (make .bob/skills/ if it is not there), so you end up with:

in the kit folder
.bob/skills/ghh-coding-standard/SKILL.md
.bob/skills/ghh-coding-standard/sku-format.md

Read it first. This is what Bob will follow:

Show SKILL.md
.bob/skills/ghh-coding-standard/SKILL.md
---
name: ghh-coding-standard
description: Global House coding standard for JavaScript services. Use when writing or reviewing code that handles products, SKUs, stock levels, prices or Thai baht amounts.
---

Follow these rules for any Global House JavaScript code. Read `sku-format.md` in this folder when you need the SKU rules.

<Steps>
<Step>
Money is Thai baht (THB). Show it as `฿1,234.50`: the ฿ sign, thousands separators, two decimals. Never use `$`. Keep prices as numbers in code and format them only when displaying.
</Step>

<Step>
SKUs follow `GH-<CAT>-<NNNN>`, for example `GH-CEM-1001`. Compare SKUs case-insensitively but always store and return them in upper case.
</Step>

<Step>
Stock on hand is a whole number and is never negative. Any code that subtracts stock must check that enough stock exists first and return a clear error if not.
</Step>

<Step>
Validate every value that comes from a request (query string, body, params) before using it. Reject unknown branch codes, unknown statuses and out-of-range numbers with HTTP 400 and a message that says what is allowed.
</Step>

<Step>
Product names are stored in both English and Thai. Keep Thai text as UTF-8 and never truncate by bytes. Search must work in both languages.
</Step>

<Step>
Never put keys, tokens or passwords in source files. Read them from environment variables.
</Step>
</Steps>

When you finish, list which of these rules you applied.
Show sku-format.md (Bob reads it only when it needs it)
.bob/skills/ghh-coding-standard/sku-format.md
# SKU format

`GH-<CAT>-<NNNN>`

| Code | Category |
|------|----------|
| CEM | Cement & Structure (ปูนและโครงสร้าง) |
| ROF | Roofing (หลังคา) |
| PLB | Plumbing (ประปา) |
| ELC | Electrical (ไฟฟ้า) |
| PNT | Paint (สี) |
| TIL | Tiles & Flooring (กระเบื้องและพื้น) |
| TLS | Tools (เครื่องมือช่าง) |
| GRD | Garden (สวน) |
| DEC | Home Decor (ของตกแต่งบ้าน) |
| DRW | Doors & Windows (ประตูหน้าต่าง) |

`NNNN` is four digits starting at 1001 within each category.

Valid pattern: `/^GH-(CEM|ROF|PLB|ELC|PNT|TIL|TLS|GRD|DEC|DRW)-\d{4}$/`

Branch codes: `KKN` Khon Kaen, `ROE` Roi Et, `UDN` Udon Thani.

Tip

Do not look for the skill in Bob yet. Create the custom mode in step 2, then reopen Bob once in step 3. That one reopen loads both.

If you cannot see the skill you added, reopen Bob. Quit it completely (closing the window is not enough), start it again, and look in the Skills tab.

2

Create the custom mode: GHH Data Analyst8 min

A mode sets a role, picks which tool groups Bob may use, and can restrict which files it may edit. This one can read, use MCP tools and skills, and may only write Markdown files in reports/.

Create .bob/custom_modes.yaml in the kit folder and paste this in:

.bob/custom_modes.yaml
customModes:
  - slug: ghh-data-analyst
    name: GHH Data Analyst
    description: Answers stock and sales questions for Global House branches and writes short reports.
    roleDefinition: >-
      You are a data analyst for Siam Global House, a Thai home-improvement retailer.
      You answer questions about branch stock and sales using the ghh-inventory MCP tools,
      never from memory. You show money in Thai baht as ฿1,234.50. You answer in the
      language the user writes in, and you keep product names in both English and Thai when
      you list products.
    whenToUse: Use this mode for questions about stock levels, reorders and sales at a Global House branch.
    customInstructions: |-
      Always call a ghh-inventory tool before stating any stock or sales number.
      If a tool returns an error, show the error text and ask the user what to change.
      Do not guess a branch. If the user does not name one, ask which of KKN, ROE or UDN.
      When you write a report, save it as Markdown under reports/ and start it with the data date.
      Keep answers short: a one-line finding first, then a small table or list.
    groups:
      - read
      - mcp
      - skill
      - - edit
        - fileRegex: "^reports/.*\\.md$"
          description: Markdown reports in the reports/ folder only

Tip

The key line is fileRegex: "^reports/.*\\.md$". It is a hard limit, not a polite request. If you ask this mode to edit a .js file, it cannot. That is why custom modes are safe to hand to non-developers.

Do not look for the mode in Bob yet. Reopen Bob once in step 3, and the skill and the mode both load.

If it does not work
  • Mode not in the picker after you reopen Bob: check the file is .bob/custom_modes.yaml (with the dot) in the kit folder, and the first line is customModes:.
  • YAML is strict about spaces. Use spaces, not tabs. Copy the block as it is.
  • Still stuck: copy the file answers/lab1/custom_modes.yaml to .bob/custom_modes.yaml.

Meet the built-in modes, then ask a plain question10 min

Open the Bob chat and look at the mode picker.

  • Ask: answers questions. Changes nothing.
  • Plan: designs the work and writes plans. Edits only text files.
  • Agent: reads, edits and runs commands to finish a task.

Try Ask first:

Ask mode

What does the data/ folder contain? Which files would I read to find products that are running out of stock at Khon Kaen?

You should see

Bob lists the four data files and points at stock.json (stock levels) and products.json (names).

Now the real question, with no stock server connected yet. Stay in Ask mode:

Ask mode

Which products are sold out or low on stock at Khon Kaen (KKN)? Give me SKU and English name, as a short list.

Bob will open files and work it out. Write down: how long it took, how many files it opened, and the answer. You will compare in step 8.

Tip

"Low" means onHand is at or below reorderPoint. Bob does not know that rule yet, so it may guess a different one. That is the problem tools solve.

6

Connect the MCP server10 min

The kit has a small MCP server in lab1/mcp/inventory-server.js. It gives Bob four read-only tools:

ToolAnswers
get_low_stockWhat is low or sold out at a branch?
get_productPrice and stock of one product, by SKU or by name in English or Thai
get_sales_summaryRevenue and top products over the last N days
suggest_reorderHow much to order, and what it costs

Bob needs to know how to start it. Generate the config for your laptop, with the right folder paths filled in:

terminal, inside the kit folder
npm run mcp:config -- --write

This writes .bob/mcp.json. It looks like this (your paths will differ):

.bob/mcp.json
{
  "mcpServers": {
    "ghh-inventory": {
      "command": "/path/to/node",
      "args": ["/path/to/kit/lab1/mcp/inventory-server.js"],
      "alwaysAllow": ["get_low_stock", "get_product", "get_sales_summary", "suggest_reorder"],
      "disabled": false
    }
  }
}

Now open Bob settings, go to MCP, and check ghh-inventory is listed and connected with four tools.

You should see

The server shows as connected, with get_low_stock, get_product, get_sales_summary and suggest_reorder listed.

Careful

The server talks to Bob over standard output. If you edit it, never use console.log in it. Use console.error. A stray console.log breaks the connection.

If it does not work
  • Listed but not connected: click Restart server next to it in the MCP tab.
  • Not connected: run the server by hand in a terminal, inside the kit folder (commands below). It should print ghh-inventory MCP server ready and wait. Press Ctrl+C to stop. A crash like ENOENT ... data/branches.json means you skipped npm run setup.
  • Connected but no tools: open the server in settings and check no tool is switched off.
  • Another way to add it: bob mcp add exists in Bob CLI, but the file above is simpler.
terminal, step 1
npm install
terminal, step 2: creates the data/ folder
npm run setup
terminal, step 3: should print ready and wait
node lab1/mcp/inventory-server.js

What you learned

  • A skill teaches Bob how your team works. Write it once, every task benefits.
  • A mode sets a role and hard limits on tools and files.
  • An MCP server gives Bob live data and actions. Good descriptions on the tools matter, because Bob picks tools by reading them.
  • MCP servers run code on your laptop. Only add ones you trust, and read what they do.
