Create an app with Bob

Learn how to implement a web app with Bob.

Time
40 minutes
Where
Bob IDE, the lab2/starter folder
You build
A stock dashboard with an API and a web page
Done when
Khon Kaen shows 4 sold-out products

Khun Somchai opens one page every morning to see what needs ordering. You will not write this by hand. You will plan it with Bob, let Bob build it, and then check what Bob built.

Tip

40 minutes is tight on purpose. The starter already has the data loader and a server that says hello. Bob builds the rest. Step 3 and 4 are what matter. Do not polish.

1

Open the starter and read the spec4 min

In the Bob IDE, File, Open Folder, and open lab2/starter. Then run it once, in a terminal inside that folder:

terminal, inside lab2/starter
npm install
npm start

Open http://localhost:3000/api/health. You should see {"ok":true,"asOf":"2026-11-16"}. Stop the server with Ctrl+C.

Now read SPEC.md and AGENTS.md. The spec says what to build. AGENTS.md holds rules Bob follows in every task in this folder. The lab 1 skill is also here, in .bob/skills/.

If it does not work
  • EADDRINUSE: something else uses port 3000. Run PORT=3001 npm start on Mac or Linux, or set PORT=3001 && npm start on Windows, and use 3001 below.
  • Cannot find module: run npm install inside lab2/starter.
  • Skipped lab 1? Nothing to do. The skill is already in the starter folder.
2

Plan first, in Plan mode8 min

Switch to Plan mode. Plan mode can read your files and write only text files. It cannot change code, so it is a safe place to think.

Plan mode

Read SPEC.md, AGENTS.md and data/SCHEMA.md. Make a plan to build the stock dashboard: which files you will create or change, in what order, and how we will test it. Keep it to 10 lines. Do not write code yet.

Read Bob's plan. Check three things:

  • Does it build the API before the page?
  • Does it put the status rules (out, low, over, ok) in one function, not copy them around?
  • Does it say how to check the result?

If something is off, say so: "Put the status rules in src/data.js, and add a test for them." Plans are cheap to fix. Code is not.

3

Build the API in Agent mode10 min

Switch to Agent mode. Ask for the API first, with tests. Then the page.

Agent mode

Follow the plan. Build the API only: GET /api/branches, GET /api/stock, GET /api/stock/summary, as described in SPEC.md. Put the status logic in src/data.js. Add node:test tests in test/api.test.js. Run npm test and fix any failures. Do not build the web page yet.

Bob will ask to approve commands, such as npm test. Read each one, then approve. This is the approval workflow. It is the default, and it is how you stay in control.

You should see

Bob reports passing tests. Then you check it yourself. Start the server and open /api/stock/summary?branch=KKN. You should see "out": 4, "low": 8, "over": 4.

Check this URLYou should see
/api/stock?branch=KKN&status=out4 products, all with onHand: 0
/api/stock?branch=BKKHTTP 400 and a message that says to use KKN, ROE or UDN
/api/stock?q=hoseThe garden hose (GH-GRD-1001)
/api/stock?q=ปูน5 products, searched in Thai
If it does not work
  • Counts are different: ask Bob "Which rule order did you use for status? Compare it to SPEC.md, section Status rules." The order matters: out, then low, then over.
  • Tests pass but a URL fails: tests only cover what they test. Tell Bob the URL and what you saw.
  • Stuck for more than 5 minutes: the finished API is in lab2/solution/src/server.js. Read it, then continue.
4

Build the page10 min

Now the page. Be specific about what it shows. Bob does better with a clear picture.

Agent mode

Now build public/index.html as one file with vanilla JavaScript, no framework. Show: a branch picker, summary tiles (products, sold out, low, overstock, stock value in baht), status filter chips, a search box that works in English and Thai, and a table with name in English and Thai, SKU, status badge, on hand, reorder point, days of cover. Colour sold out red, low amber, overstock blue, OK green. Handle API errors by showing the message. Keep it simple.

Open http://localhost:3000. Switch to Roi Et and Udon Thani. Filter by "Sold out". Search for ปูน.

You should see

Khon Kaen shows 4 sold out and 8 low. Stock value is ฿1,306,912.28. Roi Et shows 0 sold out and 5 low.

Tip

Something looks off? Do not edit the code. Tell Bob what you see: "The Thai names are cut off" or "The badges are hard to read". Describe the problem, not the fix.

5

Check what Bob built5 min

AI code needs a human check. Switch to Ask mode and review the work:

Ask mode

Review src/server.js and public/index.html for problems: unvalidated query parameters, status rules written in more than one place, user text put into the page without escaping, missing error handling. List what you find with file and line. Do not change anything.

Pick one finding and ask Agent mode to fix it. This is the habit to keep: build, review, fix. Lab 3 automates the review step.

6

Stretch: reorder suggestions3 min

Done early? Add the "Suggest reorder" button from the spec.

Agent mode

Add GET /api/reorder as described in SPEC.md, with tests, and a Suggest reorder button on the page that shows the list and the total estimated cost in baht.

You should see

For Khon Kaen: 12 products to order, estimated total ฿228,724.17. Check the first line: GH-CEM-1001, 402 bags, ฿46,129.50.

Keep your app for lab 3

Lab 3 puts this app on GitHub. Make sure npm test passes in lab2/starter. If your app is a mess, no problem: lab 3 has a finished copy in lab3/repo.

What you learned

  • Plan before you build. A bad plan is a ten-second fix.
  • Ask for the API and tests first, then the page. Small steps give small mistakes.
  • AGENTS.md and skills give Bob the rules once, so you do not repeat them in every prompt.
  • Always check the result against numbers you know. Passing tests are not proof.

For the facilitator

The finished app is in lab2/solution and runs with npm run app from the kit folder. If a participant is behind at minute 25, give them the solution and let them skip to step 5.

Expected counts for the check: Khon Kaen out 4, low 8, over 4. Roi Et out 0, low 5, over 0. Udon Thani out 0, low 8, over 0.
